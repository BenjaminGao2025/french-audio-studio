## Project rules

- All data flows through the typed API layer in src/api/ (client, types, real, mock, hooks). Mock adapter is used only with VITE_USE_MOCK=1 (`npm run dev` sets it via .env.development; `npm run dev:api` uses the real adapter through the Vite proxy); production uses the real adapter and the bundler drops the mock; real adapter targets a separate FastAPI backend. No Lovable Cloud / Supabase / server functions — the backend lives in another repo. Why: this app is the frontend for an existing FastAPI site.
- Shared UI lives in src/components/fr/kit.tsx (AppShell for overview pages, BlockShell for focused blocks); non-component exports (meta, btn, navTo, withBlock) live in kit-utils.ts so react-refresh stays clean. Why: keeps "one screen, one task" consistent.
- No /m phone-frame routes: pages are responsive (AppShell shows a bottom tab bar under md). Why: the app ships inside the host site, not as a side-by-side preview.
- Theme presets are CSS-variable blocks in src/styles.css: ink-blue is the default, sage is opt-in via <html data-theme="sage">; dark mode via .dark. Switched in Settings (src/theme/theme.ts). Why: must match the host site's design system.
- Fonts are bundled via Fontsource (no Google Fonts requests); no external telemetry. Why: the host site enforces a strict CSP.
- i18n via src/i18n (t/useT), zh-CN default, toggle in Settings. Why: the user is a Chinese speaker learning French.
- `npm run build` emits the SPA to `../static/app` (base `/app/`) and is served by FastAPI (`routers/app_shell.py`); no TanStack Start, no inline scripts. The build output is committed, so rebuild in the same commit as any frontend change. Why: the host site's CSP forbids inline scripts, and Docker has no Node stage.

- Block lifecycle is shared through useBlockFlow; Today appends block ids and destinations are computed before mutations. Why: cache refresh must not determine the next block.
- Listening counts only successful AudioButton playback; writing submissions use a per-session ref guard outside timer state updates. Why: failed audio and StrictMode must not create false activity or duplicate submissions.
- There is no human tutor or course teacher: scores are AI estimates, and the app has no tutor-session, human-score or calibration screens. The old `tutor_sessions` table is left in the database, unused. Why: the user studies with AI only, so those screens would be dead ends.
- There is no course or textbook track: no `course` lane, plan block or hours target (the 180 min/week went to intensive reading +90 and shadowing +90). Tuesday and Thursday 11:15 are intensive reading (`/reading`, which opens the legacy `/study` breakdown) and shadowing (`/shadow`). Old `course` study_time rows stay in the database and still count toward total hours, but belong to no lane. Why: the user has no course; those screens and targets would be dead ends.
